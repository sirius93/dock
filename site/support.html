Support

Dock is young — the list below is the real, current gaps, not a generic FAQ template.

Troubleshooting

A link isn't routing anywhere

Check three things, in order: the app is installed as a PWA (not just open as a regular tab — Chrome's address bar shows an install icon when one's available); the matching rule is enabled in Settings → Apps and rules; and the link's domain matches a rule's pattern exactly (built-in rules only cover *.google.com paths, not every Google subdomain).

It opened a new window instead of using my existing one

Dock only tracks windows Chrome reports as app-type windows (windowType: "app") — a PWA you installed, not a regular browser tab that happens to be on the same page. If you're on mail.google.com in a normal tab rather than the installed Gmail app, Dock won't see it as "your Gmail window."

It routed to the wrong Google account

Dock reads the account from the link itself — the authuser= value or a /u/N/ path segment — in that order. If a link has neither (no account hint at all), it falls back to whichever window for that app you focused most recently. If that guess is consistently wrong, the link you're clicking may just not carry an account hint — that's a source-side thing, not something Dock can recover on its own yet.

Switching accounts inside the PWA opened a duplicate window

This should reuse an already-open window for the account you switched to, not duplicate it — if you're seeing a duplicate, that's a real bug, not expected behaviour. Please file an issue with which apps/accounts were involved.

The Ctrl/Cmd+Shift+Space shortcut doesn't open the switcher

Another extension or the OS may already be using that combination. Go to chrome://extensions/shortcuts and rebind Dock's "Open the Dock switcher" command to whatever's free.

Shift-click bypass isn't working on a site I added a custom rule for

This is a known limitation, not a bug: Shift-click bypass currently only works on Google Workspace pages. Granting host permission for a custom rule's domain lets Dock route links there, but it doesn't extend the separate content script that listens for Shift-click — that's still Workspace-only for now.

I don't see a favicon-overlay option anymore

It was removed. It shipped as a Settings checkbox that saved a preference nothing actually read — dead UI — so it came out rather than stay as a toggle that did nothing. It's still a real idea from the original spec, just not built yet.

Reporting a bug

Open an issue on GitHub — it's the only support channel there is right now, no email, no chat. Include: your Chrome version, whether the app in question is installed as a PWA, the URL pattern that misrouted (or didn't route), what you expected instead, and — for anything account-related — how many Google accounts you have signed in and which one hit the issue.

Requesting a feature or a new built-in rule

Also a GitHub issue. If it's a rule for an app you use as a PWA that isn't already built in (check Settings for the current list), you don't have to wait on anyone — add it yourself from Settings → Apps and rules with a match pattern, no code required.

Still stuck?

Open an issue with as much detail as you can — logs, Chrome version, what you clicked and what happened instead.
